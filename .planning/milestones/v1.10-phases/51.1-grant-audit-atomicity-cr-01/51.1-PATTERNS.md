### `crates/brokerd/src/audit.rs::record_github_grant` (service, CRUD)

**Analog:** `crates/brokerd/src/server.rs:1546-1588` (the sanctioned CAS+append pattern) and `crates/brokerd/src/audit.rs:1065-1075` (`append_event`'s own autocommit-branch use of `Transaction::new_unchecked`, the exact mechanical primitive to reuse).

**Current (unfixed) shape, verified live this session** (`crates/brokerd/src/audit.rs:537-567`):
```rust
pub fn record_github_grant(
    conn: &rusqlite::Connection,
    key: &[u8],
    session_id: &str,
) -> Result<()> {
    let rows_affected = conn.execute(
        "INSERT OR IGNORE INTO session_grants (session_id, grant_type, granted_at) \
         VALUES (?1, ?2, ?3)",
        rusqlite::params![session_id, "github.pr", chrono::Utc::now().to_rfc3339()],
    )?;

    // Replay-suppression: only emit the authorize event on a FRESH grant.
    if rows_affected == 1 {
        let session_uuid = uuid::Uuid::parse_str(session_id)?;
        let (parent_id, parent_hash) = match current_chain_head(conn, session_id)? {
            Some((id, hash)) => (Some(id), Some(hash)),
            None => (None, None),
        };
        let event = Event::new(
            uuid::Uuid::new_v4(),
            parent_id,
            session_uuid,
            format!("grant:github.pr:{session_id}"),
            "github_grant_authorized".to_string(),
            chrono::Utc::now(),
            vec![],
        );
        append_event(conn, key, &event, parent_hash.as_deref())?;
    }
    Ok(())
}
```
Note: `conn.execute(...)` and `append_event(conn, ...)` are two independent
autocommit statements — the bug. Signature is locked to `&rusqlite::Connection`
(shared reference) across 12+ call sites (`cli/caprun/src/main.rs:1255`,
4 in-crate `audit.rs` unit tests, 2 `confirmation.rs` unit tests,
`s38_github_pr.rs:319`, `audit_chain_fork_regression.rs:68`) — do not widen to
`&mut Connection`.

**Mechanical primitive to use instead — `audit.rs:1065-1075`** (`append_event`'s
own autocommit branch, verbatim, DESIGN-authorized 2026-08-05 amendment):
```rust
if conn.is_autocommit() {
    let tx = rusqlite::Transaction::new_unchecked(
        conn,
        rusqlite::TransactionBehavior::Immediate,
    )?;
    let hash = append_at_head(&tx)?;
    tx.commit()?;
    Ok(hash)
} else {
    append_at_head(conn)

```
`Transaction::new_unchecked(conn: &Connection, behavior)` takes a **shared**
reference — the exact kind `record_github_grant` already has at every call
site. This is why the fix uses `new_unchecked`, not
`conn.transaction_with_behavior(...)` (which needs `&mut Connection`).

**The full fix (empirically compiled and run by RESEARCH.md this session as a
throwaway prototype, then deleted — reproduce, don't reinvent):**
```rust
pub fn record_github_grant(
    conn: &rusqlite::Connection,
    key: &[u8],
    session_id: &str,
) -> Result<()> {
    let tx = rusqlite::Transaction::new_unchecked(
        conn,
        rusqlite::TransactionBehavior::Immediate,
    )?;

    let rows_affected = tx.execute(
        "INSERT OR IGNORE INTO session_grants (session_id, grant_type, granted_at) \
         VALUES (?1, ?2, ?3)",
        rusqlite::params![session_id, "github.pr", chrono::Utc::now().to_rfc3339()],
    )?;

    if rows_affected == 1 {
        let session_uuid = uuid::Uuid::parse_str(session_id)?;
        let (parent_id, parent_hash) = match current_chain_head(&tx, session_id)? {
            Some((id, hash)) => (Some(id), Some(hash)),
            None => (None, None),
        };
        let event = Event::new(
            uuid::Uuid::new_v4(),
            parent_id,
            session_uuid,
            format!("grant:github.pr:{session_id}"),
            "github_grant_authorized".to_string(),
            chrono::Utc::now(),
            vec![],
        );
        // append_event detects the enclosing transaction (tx.is_autocommit()
        // == false) and appends at the locked durable head WITHOUT opening a
        // nested transaction.
        append_event(&tx, key, &event, parent_hash.as_deref())?;
    }
    tx.commit()?;
    Ok(())
}
```
Key mechanics (verified against `rusqlite` 0.32.1 vendored source, and
independently proven via a compiled-and-executed prototype):
- `conn.is_autocommit()` (used inside `append_event`, line 1065) delegates to
  SQLite's native `sqlite3_get_autocommit()` — real connection state, not a
  rusqlite bookkeeping flag — so it correctly reports `false` once this
  function's own `Transaction::new_unchecked` has issued `BEGIN IMMEDIATE`.
- `Transaction`'s `Drop` defaults to `DropBehavior::Rollback`
  (`rusqlite-0.32.1/src/transaction.rs:127,242-246`) — any `?`-propagated
  error before `tx.commit()` rolls back BOTH the staged `session_grants` row
  and any partial append work. Fail-closed by construction.
- `tx.execute(...)` / passing `&tx` (which `Deref`s to `&Connection`) into
  `append_event(&tx, ...)` and `current_chain_head(&tx, ...)` is exactly how
  the transaction is "joined" rather than reopened.

**Error handling pattern:** No explicit `try/catch`-equivalent needed beyond
`?` propagation — this is the project's house style throughout `audit.rs`
(every helper returns `anyhow::Result` via `Result` alias and uses `?`
unconditionally; see `append_event`, `current_chain_head`, `reserve_created_pr`
all following the same shape).

**Docstring update required (Pitfall 1 from RESEARCH.md):** the current
docstring at `audit.rs:513-536` says "Two writes under the caller's
connection: 1. ... 2. ..." — describes the OLD two-phase shape. Update in the
same commit to describe the new one-transaction shape, or it becomes a fresh
instance of the AR-05/AR-06 comment-drift class immediately.

```rust
// crates/brokerd/tests/grant_audit_atomicity_regression.rs
// Mirrors crates/brokerd/tests/audit_chain_fork_regression.rs's style (unique
// :memory: or temp-file DB per test, direct brokerd::audit:: calls, no seams).
use brokerd::audit::{has_github_grant, open_audit_db, record_github_grant, verify_chain, SCHEMA_DDL};

const TEST_KEY: &[u8] = b"caprun-grant-atomicity-test-key-01!";

#[test]
fn append_failure_after_grant_insert_rolls_back_and_retry_yields_exactly_one() {
    let conn = open_audit_db(":memory:").expect("open_audit_db");
    let session_id = uuid::Uuid::new_v4().to_string();

    // Deterministic, sub-millisecond fault: force append_event's internal
    // current_chain_head SELECT (and the events INSERT) to fail, AFTER
    // session_grants has already been staged inside record_github_grant's
    // own transaction.
    conn.execute("DROP TABLE events", []).expect("drop events table");

    let result = record_github_grant(&conn, TEST_KEY, &session_id);
    assert!(result.is_err(), "append failure must propagate as Err");

    let grant_rows: i64 = conn
        .query_row(
            "SELECT COUNT(*) FROM session_grants WHERE session_id = ?1",
            rusqlite::params![session_id],
            |row| row.get(0),
        )
        .unwrap();
    assert_eq!(grant_rows, 0, "the failed append must roll back session_grants too");
    assert!(!has_github_grant(&conn, &session_id));

    // Repair the schema (idempotent CREATE TABLE IF NOT EXISTS) and retry.
    conn.execute_batch(SCHEMA_DDL).expect("recreate events table");
    record_github_grant(&conn, TEST_KEY, &session_id).expect("retry must succeed");

    let grant_rows_after: i64 = conn
        .query_row(
            "SELECT COUNT(*) FROM session_grants WHERE session_id = ?1",
            rusqlite::params![session_id],
            |row| row.get(0),
        )
        .unwrap();
    assert_eq!(grant_rows_after, 1);
    let event_rows: i64 = conn
        .query_row(
            "SELECT COUNT(*) FROM events WHERE session_id = ?1 AND event_type = 'github_grant_authorized'",
            rusqlite::params![session_id],
            |row| row.get(0),
        )
        .unwrap();
    assert_eq!(event_rows, 1, "retry must yield EXACTLY ONE authorization event");
    assert!(has_github_grant(&conn, &session_id));
    assert!(verify_chain(&conn, &session_id, TEST_KEY));
}
```

**Pitfall 2 (from RESEARCH.md, applies directly to this file):** do not
`query_row` against `events` between the forced `DROP TABLE` and the
`SCHEMA_DDL` repair — only `session_grants` is safe to query in that window
(it was never dropped). Querying `events` before the repair throws "no such
table: events" and produces a confusing panic instead of a clean assertion
failure.

## Shared Patterns

### Transaction join-via-`is_autocommit()` (the single choke-point pattern)
**Source:** `crates/brokerd/src/audit.rs:1065-1075` (mechanism) +
`crates/brokerd/src/server.rs:1553-1588` (conceptual shape to mirror) +
`crates/brokerd/src/confirmation.rs:1163,1179` and `server.rs:1184,1226`
(two more production instances of the same "CAS/insert then conditional
`append_event`, one transaction" pattern).
**Apply to:** `record_github_grant` only, for this phase. Do not invent a
second append entry point or a raw `INSERT INTO events` — the DESIGN doc's
"choke point" invariant requires exactly one public append entry point
(`append_event`).

### Fail-closed rollback via `Transaction::Drop`
**Source:** `rusqlite-0.32.1/src/transaction.rs:127,242-246` (vendored
dependency; `DropBehavior::Rollback` is the default) — exercised throughout
`audit.rs`'s existing transaction call sites.
**Apply to:** `record_github_grant`'s fix — no explicit rollback code needed;
any `?`-propagated error before `tx.commit()` rolls back automatically.

### `anyhow::Result` + `?` propagation, no custom error types
**Source:** pervasive throughout `crates/brokerd/src/audit.rs` (`append_event`,
`current_chain_head`, `reserve_created_pr`, `has_github_grant`, etc.) — the
project's `Result` alias resolves to `anyhow::Result` in this crate.
**Apply to:** `record_github_grant`'s fix body — keep using `?` exactly as
the current (unfixed) function already does; no new error-handling shape is
introduced by this fix.
